# 素材理解与编排

## 先看素材，再写分镜
1. 把主口播、图片、辅助视频、录屏分别编号。建立asset_manifest.json：id、相对path、type、尺寸/方向、视频duration/fps/audio、实际可见内容、重要区域、已烧录字幕、质量问题。用户已解释用途时保留其说明，仍核对画面。
2. 图片实际打开查看；含文字的截图读取关键文字，缩放确认，不猜模糊数字。视频在开头、中间、结尾和镜头/动作变化处抽帧，选用段落另作连续检查；记录可用in/out。未听音只能写音轨存在、未听审，不能判断声音内容。
3. 将实际讲话拆成“观点、案例、证据、步骤、对比、结论”，给每段选择最能增进理解的素材。按直接相关性、信息增量、清晰度、时效/语境是否一致判断，不编造精确分数。没有帮助就不用；不为凑热闹把所有素材塞满。
4. 为采用素材记录：asset_id、口播cue引用、成片start/end、素材in/out、使用理由、裁切、布局、人物是否显示、重点区域、声音策略。未采用素材记录简短理由，例如重复、无关、太糊或缺少可验证语境。

## 选择展示方式
| 讲话需要 | 优先画面 | 安排 |
| --- | --- | --- |
| 具体人物、地点、产品或案例 | 对应真实图片/视频 | 在提到对象时出现，留足识别时间 |
| 数据、政策、报道、结果 | 对应原始截图/图表 | 放大相关区域，框出关键处，保留日期、单位和必要上下文 |
| 操作、流程、工具使用 | 真实录屏的关键完整操作 | 先结果后步骤或按讲述顺序，保留动作起止，不截断关键反馈 |
| 抽象逻辑、因果、价值 | 内容对应的知识图解 | 素材不能说明时回图解，不把场景画面冒充证据 |
| 前后效果或不同方案 | 同尺度、同语境的对比 | 先后展示或明确分栏，不能用无关素材伪造前后结果 |
| 核心观点、情绪或总结 | 真人主画面 | 回到真人，形成停顿和记忆点 |

- 默认不联网补素材。确需补充而未获授权时，优先利用现有素材与图解完成；用户明确要求搜索则按要求搜索并记录来源。
- 建议图片2—4秒、证据截图4—6秒、动作片段按动作完整性决定；这些是阅读起点，不是固定时长。由实际讲述决定最终入出点，不均分素材、不拉伸口播。
- 讲到对象时或必要时提前约0.2秒切入，讲完后回真人或下一个论点；不得为了转场次数打断阅读。

## 构图和声音
- 延续毛玻璃底色、统一字体/强调色；素材先等比contain，横图可做居中大卡，不强裁成竖屏。竖图/录屏需要更大高度；证据画面优先可读性。
- 圆形真人窗默认保留白边和阴影，取主口播同一成片时刻。若遮挡产品、操作按钮、文字或人物，可逐场换角、缩小或暂时隐藏；不固定在右下角遮一切。每次回切保持人物比例自然。
- 裁辅助素材时写asset_crop，保留关键信息、数字、比例尺和来源。focus框只标真实可见区域；不重写截图数字或用装饰箭头暗示未经证实的因果。
- 主口播音轨持续、自然语速不变；辅助视频默认静音。确需展示辅助原声时必须先检查其内容，安排对白留白并做明确混音；当前内置渲染器不支持辅助原声混入，需另写合成步骤，不能传一个字段就声称已完成。
- 素材自带字幕/标题时检查重复；可避开字幕区域或选择其他镜头，无法处理时说明。不能用新字幕把事实限定条件遮掉。
- 时长不足：缩短素材覆盖并回真人/图解，或选另一有效片段；不偷偷循环、变速或冻结动作。

## 交付检查
- 每条插入都有可解释的内容目的；不用完全部素材也可以完成作品。
- 看得清文字/产品/动作，不与圆窗、标题或单行字幕相撞；保持完整必要上下文。
- asset_manifest.json保留采用/弃用理由；plan.json保留实际in/out和布局，输出review记录实际检查范围与未听审项。
- 素材语义判断由调用本Skill的模型执行；脚本只按计划合成，不声称脚本具备自动理解、OCR或镜头分析功能。

内容优先编排（最新默认）：先把口播整理成“观众的问题→关键区别→原因或机制→例子或对比→行动要点”的逻辑链，逐项核对实际讲话，不能硬套结构或添加未说过的事实。每场只解释一个问题，箭头必须表达真实因果、流程或归属，不能用箭头连接相反概念造成误导。知识图解是主画面，真人是声音与信任的辅助，默认show_presenter=false，开头封面与结尾按需要露出真人；不要每场强塞圆窗或大人物框。可见真人时仍执行完整头发与脸的规则。纯内容path支持2–3个真实时刻节点，采用纵向大卡片与逐步连线，空间延展到画板下部；compare/list/amplifier也使用更大的内容区。每个节点随实际讲话出现，一次只推进一步；先后顺序、对比和因果分别选用正确模板。避免用图解复述整句字幕、堆满元素、先给结论再补过程导致看不懂。每段概述说明“这一段解决什么”，主标题点明论点，正文只保留必要关键词。人工验收新增“观众能否不倒回也跟上逻辑”的检查，不以炫技或人物曝光量代替理解度。

逻辑关系必须区分：因果/流程才用path箭头；概念定义用definition（lead、body、body_at），不加否定划线或流程箭头；并列问题/职业/要点用list；互斥选择/差异用compare；纠正旧观点才用statement。禁止把“个人IP的优势是低成本”画成流程，也不要用箭头暗示并列属性互相导致。definition的body只在实际讲到body_at后出现。
